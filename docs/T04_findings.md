# T04 記錄結構解析與影像取得（完成 2026-09-09）

## 重大進展：檢索結果是伺服器端渲染，可直接解析
不需要 AJAX。結果 HTML 結構：
```
div.data_record.tr_like
  input.result_selecter[value]      -> 內部記錄 ID
  span.meta_zong_mark               -> 資料類型（議事錄/公報/檔案）
  a[target=_blank]                  -> 典藏號
  span.field_name / span.field_value 成對 -> 各欄位
```
**→ 全量採集在技術上已無障礙。** 100 筆/頁，可分頁、可排序。

## 清單頁實際回傳的欄位（每筆 5 個，填充率 20/20 = 100%）
| 欄位 | 範例 |
|---|---|
| 典藏號 | `001-01-01OA-00-3-3-0-00003` |
| 資料類型 | 議事錄 |
| 卷/冊號 | `001-01-01OA-00` 臺灣省參議會第一屆第一次定期大會 |
| 會議階層 | 臺灣省參議會/第一屆/第一次定期大會/- |
| **分類階層** | `圖表影像附錄/議員題名錄/總目`、`宣言賀詞/總綱/總目` |
| 資料日期 | 1946-04-30 ~ 1946-05-15 |
| 提供方式 | **線上閱覽** |

## 解決了 T03 遺留問題
`category_level`（分類階層）是**三層階層字串** `大類/中類/小類`，不是單一詞。
先前查 `質詢` 失敗是因為缺階層 → 需用完整路徑或前綴。

## 重要限制（新發現）
**內容摘要（abstract）不在清單頁。** 它可被檢索（`abstract_mask=水利` → 1,938 筆），
代表資料庫裡有內容，但要取得摘要文字必須進到單筆詳目頁。
`Display/` 端點目前回傳空字串（2 bytes），詳目頁的正確呼叫方式尚未解出。

## 對專案方向的影響
- 採集管線可行性從「未知」變成「已驗證」——清單層 metadata 可全量取得
- **但真正決定成敗的是摘要文字能否批次取得**。這是目前唯一的關鍵未知數
- 影像 OCR 測試暫緩：若摘要可取得，OCR 可能完全不需要；若摘要取不到，才回頭做 OCR

## 轉 T05
解出單筆詳目頁的取得方式，確認「內容摘要」的實際文字內容與填充率。
